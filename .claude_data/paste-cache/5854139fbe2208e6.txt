You make a completely valid point. If a coach already pays a monthly wholesale fee to a facility, or if they own their own private backyard court, forcing the student to pay an extra platform court fee is a terrible user experience. It would drive coaches off the platform.

We absolutely need to support this, but we need to do it without tangling up the Stripe routing or accidentally giving away Facility courts for free.

The cleanest architectural solution is to introduce the "Nepriklausoma paslauga" (Independent Service) model.

How the "Independent Service" Model Works
Instead of trying to hack the existing facility booking logic to process a 0€ payment, we separate the service from the platform's courts entirely.

Service Creation: When the coach creates a service, they select a new option: "Treneris pasirūpina vieta (Aikštelė įskaičiuota į kainą)" (Coach provides the location / Court included in price).

The Database: The service is saved with courtId = null AND a new flag: isLocationProvidedByCoach = true.

The Booking Flow: When a student books this service, the widget skips the court selection step entirely. It only asks for the Date and Time.

The Checkout: The student pays exactly what the coach asks (e.g., 40€). 100% of the funds route to the Coach.

The Calendar: The booking is created in the database with a null court. It blocks the Coach's calendar, but it completely ignores the Facility's calendar. The coach communicates the exact location to the student via the built-in messaging system or the service description.

This solves the payment routing perfectly and gives coaches total freedom.
