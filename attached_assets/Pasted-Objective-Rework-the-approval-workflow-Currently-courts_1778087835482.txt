Objective: Rework the approval workflow. Currently, courts can be submitted for approval independently of their parent facility. We need to shift this to a "Top-Down" Facility-level approval system. 

Step 1: Database Schema Updates
1. Update `facilitiesTable`:
   - Ensure it has an `approvalStatus` column (enum: 'draft', 'pending_review', 'approved', 'rejected'). Default is 'draft'.
2. Update `courtsTable`:
   - Remove the independent `approvalStatus` column from the court level, OR strictly bind it to the facility. 
   - A better approach is to change the court's status to `isActive` (boolean, default false). A court can only be viewed publicly if `isActive == true` AND its parent facility `approvalStatus == 'approved'`.

Step 2: Backend API Logic
1. Create/Update Endpoint: `POST /api/facilities/:id/submit-for-review`
   - Logic: Changes facility `approvalStatus` from 'draft' to 'pending_review'. 
   - Validation constraint: A facility can only be submitted if it has at least 1 attached court, a valid address, and basic details filled out.
2. Update Admin Approval Endpoint: `POST /api/admin/facilities/:id/approve`
   - Logic: Changes facility `approvalStatus` to 'approved'.
   - Trigger: Automatically sets `isActive = true` for all courts currently attached to this facility.
3. Update Public Queries (e.g., `GET /api/courts` or `GET /api/search`):
   - Add strict WHERE clauses: Only return courts where the joined `facilitiesTable.approvalStatus` is 'approved'.

Step 3: Frontend Owner Dashboard Updates
1. Remove the "Submit Court for Approval" button from the individual Court edit screens.
2. On the main Facility Dashboard, add a global banner/button: "Pateikti kompleksą patvirtinimui" (Submit facility for review). 
3. Disable this submit button if the facility is missing critical data (e.g., 0 courts added, no address).
4. If the facility status is 'pending_review', show a yellow badge: "Kompleksas peržiūrimas administratoriaus" (Facility is being reviewed by admin) and disable editing to prevent data mutation during review.
